## Ground rules for the session

- Read `CLAUDE.md`, `docs/WORKFLOW.md` and `docs/TESTING.md` first. Follow the loop: test build labelled above
  v0.5.0 (`v0.6.0-fix.N` in `version.txt`, touch `CMakeLists.txt`), flash on COM5 through the flash helper started
  in the background, prove on the device, let the user try it, then "document and commit".
- One PR per group on a branch `align/<group>`. After the merge, the `release-rc` skill tags `v0.6.0-rc.N` and runs
  `harness.py --ota`. The stable v0.6.0 needs the user's OK.
- Build: `. C:\Espressif\esp-idf\export.ps1`; `$env:IDF_COMPONENT_CACHE_PATH="$env:USERPROFILE\.espressif\cm_cache"`;
  `idf.py -B build\v55 -D SDKCONFIG=build\v55\sdkconfig build`. After a change to `sdkconfig.defaults`, delete
  `build\v55\sdkconfig` first.
- Every fix gets a test that fails on the old code (harness, Playwright or host). `wsl make -C tests/host` before a
  tag. A general lesson goes to `docs/LESSONS.md` (Group G lists them).
- Each group's PR ticks its BACKLOG entries (`[x] v0.6.0-rc.N, PR #n`) or strikes them with the reason, and ticks
  the item here.
- Order: Group F (PC side) can run first and in parallel in its own sessions; then A → B → C → D → E; G last.

Sizes: S < 1 h, M = a few hours including device proof, L = a session. One release candidate per group.
